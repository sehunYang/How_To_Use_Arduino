# TCA9548A Wokwi chip

A Wokwi custom chip can answer I2C but cannot start a transaction, so it cannot
pass a sketch's request through to a separate sensor chip on a channel. This
chip models the switch *and* the TSL2591s behind it (`chips/tsl2591.c`, the same
register model the standalone TSL2591 chip uses).

The generator (`withTcaChips` in `src/wokwi/phase5ProjectGenerator.ts`) reads the
recipe's wiring, drops the separate TSL2591 parts and sets:

| Attribute | Meaning |
|---|---|
| `address` | 0x70 plus the A0-A2 straps tied to 5 V (unwired straps read 0, as the breakout pulls them down). |
| `tslMask` | One bit per channel that carries a TSL2591. |

The light at channel `n` is set with the `ch0Raw<n>` and `ch1Raw<n>` controls,
in the same units as the TSL2591 chip's `ch0Raw`/`ch1Raw`.

Modelled from the TI datasheet:

- One control byte, any number of channels open; a read returns it.
- RESET low clears the control byte and keeps the switch off the bus. The
  breakout's pull-up is modelled, so an unwired RESET leaves it running.
- Sensors on two open channels both answer 0x29. SDA is open-drain, so the
  master reads the AND of their bytes, garbled data as on real hardware.

Not modelled: channel capacitance and bus speed limits, and devices other than
the TSL2591 on a channel (the generator rejects those wirings).
