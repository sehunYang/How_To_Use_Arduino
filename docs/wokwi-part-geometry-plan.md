# 계획: 브레드보드·커스텀 칩 형상 확보

**상태:** 초안 (미착수)
**작성:** 2026-07-27
**선행 작업:** `src/wokwi/partGeometry.ts` (Uno·MPU6050 형상 고정 완료)

## 1. 배경

`ReadableLayout`의 좌표는 실제 Wokwi 부품 형상에 고정되어야 의미가 있습니다. Wokwi는
도선을 **실제 핀 위치**에서 시작해 `h`/`v` 상대 명령을 적용해 그리므로, 명세의 핀 좌표가
틀리면 렌더 경로가 통째로 밀리고 검증기는 가상의 좌표계 안에서만 정합합니다.

현재 `partGeometry.ts`는 `wokwi-arduino-uno`와 `wokwi-mpu6050`만 보유합니다. 나머지는
`GEOMETRY_UNAVAILABLE`에 사유와 함께 등록되어 `unknown-part-geometry`로 **보고**됩니다.
조용히 통과시키지는 않지만, 검사를 못 하는 상태인 것은 그대로입니다.

그 결과 `chipConformanceLayout`은 `purpose: 'fixture'`로 좌표 고정을 면제받고 있습니다.
지금은 아무도 그 리그를 보고 배선하지 않으므로 허용 가능하지만, **다음 두 경우에 곧바로
막힙니다.**

- 브레드보드를 쓰는 **레시피**를 만들 때. Phase 5의 34건 중 다수가 해당할 가능성이 높습니다.
  I2C 장치를 2개 이상 붙이는 순간 버스를 나눌 무언가가 필요하고, 그게 브레드보드입니다.
- INA219·TSL2591을 쓰는 레시피의 배선도를 촬영할 때.

즉 이 작업은 Phase 5 콘텐츠 저작의 **선행 조건**입니다.

## 2. 확인된 사실

조사 결과이며, 계획의 전제입니다.

| 대상 | 상태 | 근거 |
| --- | --- | --- |
| `wokwi-arduino-uno` | 좌표 확보 완료 | `wokwi-elements/src/arduino-uno-element.ts`의 `pinInfo` |
| `wokwi-mpu6050` | 좌표 확보 완료 | `wokwi-elements/src/mpu6050-element.ts`의 `pinInfo` |
| `wokwi-breadboard*` | **공개 소스 없음** | `wokwi-elements/src`에 브레드보드 엘리먼트 부재(전체 파일 목록·`index.ts` export 확인). 내장 비공개 파트 |
| `chip-ina219`, `chip-tsl2591` | **좌표 지정 불가** | `chip.json` 필드는 `name`/`author`/`pins`/`controls`/`display{width,height}`뿐. 핀 좌표·커스텀 SVG 미지원, 배치는 시뮬레이터가 `pins` 배열 순서대로 자동 결정 |

**핵심 함의 2가지**

1. 커스텀 칩은 `display.width`/`height`로 **본체 크기를 우리가 고정할 수 있습니다.** 따라서
   미지수는 "본체 크기 × 배치 규칙"이 아니라 **배치 규칙 하나**로 줄어듭니다.
2. 브레드보드는 순수 측정 대상입니다. 핀 **이름** 규칙은 이미 알고 있고(`tp.N`/`tn.N` 레일,
   `<열><t|b>.<a~j>` 스트립) `netlist.ts`의 도통 모델이 그 위에서 정상 동작합니다. 모르는 것은
   **좌표뿐**입니다.

## 3. 목표 / 비목표

**목표**

- `wokwi-breadboard-half`의 홀 좌표를 `partGeometry.ts`에 확보
- `chip-*` 커스텀 칩의 핀 배치 규칙을 확보하고, `chip.json`의 `display`로 본체 크기 고정
- `chipConformanceLayout`이 `purpose: 'fixture'` 없이 `'recipe'`로 통과
- 측정 기반 좌표에 대한 **오차 허용 정책** 수립

**비목표**

- `wokwi-breadboard`(풀사이즈)·`wokwi-breadboard-mini`는 실제로 쓸 때 착수
- Wokwi가 파트 형상을 바꾸는 경우의 자동 추적 (6절 리스크로 관리)
- 파트 회전 지원 (`unsupported-part-rotation`은 유지)

## 4. 접근

### 4.1 측정 수단

`wokwi-cli`가 파트 단위 스크린샷을 지원합니다.

```
--screenshot-part <id>    "Take a screenshot of the given part id (from diagram.json)"
--screenshot-time <ms>
--screenshot-file <path>  (기본 screenshot.png)
```

파트 하나만 캡처하므로 그 이미지의 픽셀 좌표가 곧 파트 로컬 좌표계 후보가 됩니다.

### 4.2 방법의 검증이 먼저다 (필수 선행 단계)

**측정 방법을 신뢰하기 전에, 답을 이미 아는 파트로 방법을 검증합니다.**

`wokwi-arduino-uno`를 스크린샷으로 측정해서 나온 핀 좌표가 `partGeometry.ts`에 이미 있는
`pinInfo` 값과 일치하는지 확인합니다. 일치하면 그 방법으로 브레드보드를 측정해도 됩니다.
일치하지 않으면 (스케일·원점·여백 차이) **그 오차를 먼저 규명**하고, 규명되지 않으면 이
접근 자체를 폐기하고 4.4의 대안으로 갑니다.

이 단계를 건너뛰면 "측정했으니 맞겠지"가 되고, 그건 이번에 고친 문제와 같은 종류의
가정입니다.

### 4.3 오차 허용 정책

전사(transcribe)한 좌표와 측정한 좌표는 신뢰도가 다릅니다. `partGeometry.ts`에 출처와
허용 오차를 함께 기록하고, `pin-position-mismatch`가 그 값을 쓰도록 합니다.

```ts
source: 'wokwi-elements'   // 정확. 허용 오차 0.01px (현행)
source: 'measured'         // 측정. 허용 오차는 측정 결과에 따라 결정
```

허용 오차 상한은 **핀 피치의 1/4** 이하여야 합니다. 브레드보드 피치가 약 9.6px이므로
**2.4px 이하**를 목표로 합니다. 이보다 크면 이웃 홀과 구별되지 않아 검사가 무의미해집니다.

### 4.4 대안 (4.2가 실패할 경우)

우선순위 순으로 기록합니다.

1. **리그에서 브레드보드를 제거.** 적합성 리그는 촬영 대상이 아니므로, 브레드보드 없이
   칩을 직접 연결하면 브레드보드 좌표가 필요 없어집니다. 단 I2C 버스 공유 때문에 한 핀에
   도선 2개를 꽂아야 하고, 이는 `duplicate-endpoint` 규칙과 충돌합니다 — 그 규칙을 `fixture`
   용도에서 완화할지 결정해야 합니다. **리그 문제만 해결하고 레시피 문제는 남습니다.**
2. **Wokwi 편집기에서 수동 측정.** 브레드보드에 부품을 스냅시키면 Wokwi가 좌표를 계산해
   주므로, 저장된 `diagram.json`의 `top`/`left`에서 홀 좌표를 역산합니다. 수작업이지만
   1회성이고, 스냅된 결과는 Wokwi 자신의 계산이므로 정확합니다. **4.2가 실패하면 이쪽이
   가장 유력합니다.**
3. **레시피에서 브레드보드를 배제.** 배선을 직결로만 구성. Phase 5 콘텐츠의 표현력을
   제약하므로 최후 수단입니다.

## 5. 작업 단계

### 0단계 — 방법 검증 (게이트)

- [ ] Uno 단독 `diagram.json`으로 `--screenshot-part uno` 캡처
- [ ] 이미지에서 핀 좌표 측정 (수동 또는 이미지 처리)
- [ ] `PART_GEOMETRY['wokwi-arduino-uno']`와 대조, 오차 기록
- [ ] **판정:** 오차 ≤ 2.4px면 1단계 진행. 초과·불일치 원인 불명이면 4.4의 2번으로 전환

> 이 게이트를 통과하지 못하면 나머지 단계는 착수하지 않습니다.

### 1단계 — 브레드보드 좌표

- [ ] `wokwi-breadboard-half` 캡처 및 측정
- [ ] 홀 좌표가 규칙적 격자인지 확인 → **개별 좌표가 아니라 공식으로 저장**
      (원점 + 피치 + 레일 오프셋). 홀이 수백 개이므로 표로 두면 유지가 불가능합니다
- [ ] 공식이 실제 이름 규칙(`tp.N`, `5t.a`)과 일치하는지 교차 검증
- [ ] `partGeometry.ts`에 `source: 'measured'`와 허용 오차를 붙여 등록

### 2단계 — 커스텀 칩 배치 규칙

- [ ] `ina219.chip.json`·`tsl2591.chip.json`에 `display.width`/`height`를 **명시**해 본체 크기 고정
- [ ] 캡처·측정으로 `pins` 배열 순서 → 좌표 매핑 규칙 도출
      (예: 좌측 위에서 아래로, 이어서 우측 아래에서 위로 — DIP 관례 여부 확인)
- [ ] 규칙을 함수로 구현하고, 핀 개수가 다른 합성 칩으로 일반성 검증
- [ ] 두 칩을 `GEOMETRY_UNAVAILABLE`에서 제거

### 3단계 — 리그를 엄격 모드로 전환

- [ ] `chipConformanceLayout`을 실제 좌표로 재작성
- [ ] `purpose: 'fixture'` 제거 → `'recipe'`로 통과 확인
- [ ] L3 시뮬레이션이 계속 green인지 확인
- [ ] `purpose: 'fixture'`가 더 이상 쓰이지 않으면 **타입에서 제거할지 결정**
      (남겨두면 다음 사람이 손쉬운 탈출구로 쓰게 됩니다)

### 4단계 — 문서

- [ ] `docs/wokwi-wiring-rules.md`의 형상 절 갱신
- [ ] 측정 절차를 재현 가능하게 기록 (다음에 Wokwi가 파트를 바꿨을 때 필요)

| R5 | 작업량이 Phase 5를 지연 | 레시피가 실제로 브레드보드를 요구할 때까지 착수를 미룰 수 있음. 다만 **저작 시작 전에는 끝나야** 34건을 다시 그리지 않음 |

## 7. 미해결 질문

- **착수 시점.** Phase 3(학생 UI) 전인가, Phase 5 저작 직전인가. 배선도가 Phase 5 산출물이므로
  저작 직전이 자연스럽지만, 그때 4.4-3(브레드보드 배제)으로 밀리면 콘텐츠 설계가 흔들립니다.
- **풀사이즈 브레드보드**를 함께 확보할지. 한 번 측정하는 김에 같이 하는 편이 쌀 수 있습니다.
- `duplicate-endpoint` 규칙을 `fixture` 용도에서 완화할지 (4.4-1을 쓸 경우에만 필요).
